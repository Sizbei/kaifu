## Blocker

### B1. A non-ISO `dueDate.iso` from the vision model crashes the whole card [verified]

- `src/lib/types.ts:32-34` — `iso: z.string()` accepts anything. `src/lib/vision.ts:73` — JSON schema has no `pattern` either.
- `src/components/obligation-row.tsx:100` — `DATE_FMT.format(new Date(\`${dueDate.iso}T00:00:00+09:00\`))`. `Intl.DateTimeFormat.format(Invalid Date)` throws `RangeError: Invalid time value`.
- `src/components/ics.tsx:30-32` — `nextDay()` → `toISOString()` on Invalid Date also throws.
- No error boundary anywhere under `src/app/` → React unmounts the tree. White screen on stage.

Repro: model emits `{ iso: "2026-09-上旬", raw: "9月上旬", label: "提出" }` (relative dates like 上旬/中旬/末 are exactly what the prompt never tells it how to encode). `VisionResultSchema.safeParse` → success; `crossCheck` → conflict `{ modelSaw: "9月上旬", documentSaid: "not found in document" }`; render → RangeError. Same for `"2026-9-5"` if the model drops zero padding.

Fix (minimal): `iso: z.string().regex(/^\d{4}-\d{2}-\d{2}$/)` in `ExtractedDateSchema` and `pattern: "^\\d{4}-\\d{2}-\\d{2}$"` in `DATE_SCHEMA` (strict mode supports it). Then in `crossCheck`, an obligation whose `dueDate.iso` fails `toIso()` should keep the conflict but the UI must render `dueDate.raw` instead of calling `DATE_FMT` when `Number.isNaN(Date.parse(iso))`. Add an `error.tsx` under `src/app/` regardless.

### B2. A lease decode dies with "take a better photo" when the JUDGE Shisa call fails [verified by reading]

- `src/lib/complete.ts:14-33` — bare `fetch`, no `withRateLimitRetry`, throws on any `!res.ok`.
- `src/lib/judge.ts:315` — `await complete(...)` is not caught.
- `src/app/api/decode/route.ts:93-96` — `Promise.all([generateActionCard, judgeClause])` rejects as a whole.
- `route.ts:125-128` — every non-config error maps to `"Could not read this document. Try a flatter, better-lit photo."`

`generateActionCard` and `judgeClause` fire at Shisa in the same millisecond, which `src/lib/backoff.ts:4-8` documents as the burst the per-key limiter rejects with 429. The card path retries; the judge path does not. Result on the lease demo: the one document type with the kicker feature returns 502 with a photo hint, and the founder retakes the photo.

Fix: make `completeWithShisa` call the shared `postChat` (export it from `shisa.ts`, or move `withRateLimitRetry` into `complete.ts`); in the route wrap the judge in `.catch((e) => { console.warn("[decode] judge failed", e); return []; })` so JUDGE degrades to "no findings" instead of killing the card.

### B3. OpenAI quota/key/5xx failure is reported as a bad photo [verified by reading]

- `src/app/api/decode/route.ts:125-128` — only `VisionConfigError` (missing key) gets its own message. An OpenAI `429 insufficient_quota` (true right now), `401`, `5xx`, timeout, or `VisionSchemaError` (e.g. model returns `confidence: 85`; JSON schema at `vision.ts:115-119` has no min/max while Zod at `types.ts:85` does) all become "Try a flatter, better-lit photo."
- `src/components/kaifu-app.tsx` `decode()` — a non-2xx with a JSON body still shows `body.error`, so the user sees the photo hint.

Fix: in the catch, branch on `err instanceof OpenAI.APIError` → `status 401/403/429` → "Vision service unavailable (key or quota). Nothing to do with your photo."; `VisionSchemaError`/`VisionResponseError` → "The reader returned something we could not trust. Try again."; keep the photo hint only for OpenAI 400 `invalid_image`. Use status 503 for upstream, 502 for schema.

## High

### H1. Year-less documents: a wrong year from the model is never flagged [verified]

- `src/lib/extract.ts:352-358` `inferReferenceYear` takes the year from the model's own `dates[0].iso`; `parseJapaneseDates` then resolves every bare `9月5日` in that same year. Comparison at `:373` is on full ISO, so the year can only ever agree.

Repro (scratch A): rawText `提出期限：9月5日（金）`, model `dates:[{iso:"2025-09-05"}]`, obligation due `2025-09-05` → `conflict: null`. UI shows "Fri 5 September 2025 · 356 days ago" with no vermilion edge. Most school prints carry only 月日; this is the common case, not a corner.

Fix: give `crossCheck(vision, now = new Date())` a clock. If the document prints no fully-qualified date (`matches.find(m => m.year !== null)` is undefined), use `now.getFullYear()` as `referenceYear` and `now` as `referenceDate` (the roll-forward rule already exists at `:255-264`). Then a model year that differs from the resolved year is a real conflict. Route passes `new Date()`; tests keep passing a fixed date.

### H2. The conflict box promotes a wrong "page says" value, and the UI visibly picks a winner [verified]

Two independent regex misses, both common on real paper:

- Day-only deadlines (`提出締切：12日（金）まで` under a header `令和8年9月20日`) — no pattern in `DATE_PATTERNS` (`extract.ts:168-193`) matches `12日` alone. Scratch B: model due `2026-09-12` (correct) → `conflict.documentSaid = "令和8年9月20日（土）"` (the excursion day, wrong).
- Daiji numerals (`壱弐参拾` etc.) are absent from `KANJI_DIGIT` (`extract.ts:21-28`), although `docs/ARCHITECTURE.md:71` claims `金参千弐百円` support. Scratch: `金参千弐百円` → ¥100; `金弐拾万円也` → **¥0**; `金壱万弐千円` → ¥1,000. Deposits on leases are routinely written this way, so the model's correct ¥200,000 gets a conflict with "the page says 万円".

Then `src/components/obligation-row.tsx:52-57` renders `modelSaw` with `line-through` and `documentSaid` in bold. `docs/ARCHITECTURE.md:118-121` says the UI must not prefer the regex. It does, and in these cases it prefers the wrong one. `documentSaid: "not found in document"` is also rendered bold as if it were a value.

Fix: (1) add `壱:1, 弐:2, 参:3, 肆:4, 伍:5, 陸:6, 漆:7, 捌:8, 玖:9` to `KANJI_DIGIT`, `拾:10` to `KANJI_SMALL_UNIT`, and both sets to `KANJI_NUM`/`KANJI_D`; reject `yen === 0` at `:313`. (2) Add a day-only pattern `(?<![0-9月])(N)日(WD)?` that borrows the month from the nearest preceding full date on the page (or is skipped when none). (3) In `ConflictNotice` drop the strike-through/bold asymmetry; label the second column "Nearest date on the page" and render the `label` of the matched date next to it so the user can see it is a different line.

### H3. Advice-language guard: 13 obvious phrasings pass, and neutral restatements are blocked [verified]

`src/lib/judge.ts:127-145`. All of the following pass `assertNoAdviceLanguage` unchanged (scratch, lens 3):

`The landlord cannot charge the tenant for this.` · `The tenant is not obligated to pay this.` · `The tenant is not liable for ordinary wear.` · `This charge is not permitted under the guideline.` · `The landlord is prohibited from deducting this.` · `The tenant does not owe this amount.` · `The landlord may not deduct cleaning from the deposit.` · `Tenants are not responsible for sun-fading; the landlord bears it.` · `この費用は認められない。` · `借主が負担する必要はありません。` · `貸主はこの費用を請求することはできない。` · `この条項はガイドラインに違反している。` · `この特約は認められません。`

Every one of those is a legal conclusion in KAIFŪ's voice. Meanwhile these get **dropped**, and they are how a model restates a clause: `The tenant must restore the room at their own cost.` · `The tenant is required to pay a cleaning fee.` · `The tenant has to give one month's notice.` · `The guidance says the landlord must show an itemised breakdown.` So on stage the guard is likely to kill the genuine findings and let a "cannot charge" one through.

Fix: add to `PROHIBITED`:
`/\b(cannot|can't|may not|must not|is not (allowed|permitted|entitled)|not (obligated|obliged|liable|responsible|required) to|does not owe|prohibited|forbidden|no obligation)\b/i` and `/(認められ(ない|ません)|負担する必要は|支払う必要は|義務はない|義務はありません|請求(すること)?はできない|請求できない|違反|許され(ない|ません)|禁止|返還される|返ってくる)/`. Narrow the first pattern to second person and recommendation: `/\byou (should|must|need to|have to|ought to)\b/i` and `/\b(should|ought to)\b/i`, so "the tenant must" (restating a clause) survives while "you should" does not. Add both lists to `judge.test.ts`.

### H4. Raw upstream error text is streamed to the browser per register [verified by reading]

- `src/lib/shisa.ts:334-338` — `message: err.message`, which for a gateway failure is `Shisa request failed: 429 {"context":["authMiddleware"],"code":104,"name":"ErrAuthenticationFailed","error":"Authentication error: Too many requests…"}` (`postChat`, `:105-106` includes 300 chars of body).
- `src/components/register-output.tsx:86` renders `buffer.error` verbatim under "This level could not be written."

On stage the slider stop says "Authentication error". Fix: in `streamRegisters` send a fixed `"This register could not be generated."` and `console.warn` the detail; keep `err.message` only for `process.env.NODE_ENV !== "production"` if you want it in dev.

### H5. Timeouts are unbounded against `maxDuration = 60` [verified by reading SDK defaults]

- `src/lib/vision.ts:209` — `new OpenAI({ apiKey })` → default timeout 600 s, `maxRetries: 2` (`node_modules/openai/client.js:221,231`). `detail: "high"` + `max_output_tokens: 16000` for a verbatim A4 transcription is the slow path.
- `src/lib/retrieval.ts:81` — `QdrantClient` default timeout 300 s.
- `src/lib/graph.ts:150` — `neo4j.driver` default connection timeout 30 s; `route.ts:119` **awaits** `benchmarkFor` on every lease decode with findings, so an unreachable Neo4j host adds up to 30 s to the response.
- `complete.ts` / `postChat` — no signal / timeout.

Serial chain: vision → (card ‖ judge[embed → qdrant → shisa]) → neo4j. On Vercel the function is killed at 60 s and the client shows "The reader answered 504". Fix: `new OpenAI({ apiKey, timeout: 40_000, maxRetries: 1 })` in both `vision.ts` and `embed.ts`; `new QdrantClient({ url, apiKey, timeout: 3_000 })`; `neo4j.driver(uri, auth, { connectionTimeout: 3_000, connectionAcquisitionTimeout: 3_000 })`; pass `AbortSignal.timeout(30_000)` into `postChat` from `generateActionCard`/`completeWithShisa`. Make `benchmarkFor` best-effort with `Promise.race` against a 2 s timer.

## Medium

### M1. "Only a summary" notice gives the wrong reason for `unknown` [verified by reading]

`route.ts:89` sets `summaryOnly` for `docType === "unknown"` regardless of confidence; `src/components/action-card.tsx:15-27` always says "The photo was not clear enough to read the dates and amounts". A crisp photo of a bank letter (confidence 0.95) is told its photo was bad. `ARCHITECTURE.md:139-141` requires the UI to "say why". Fix: in `SummaryOnlyNotice`, branch on `card.docType === "unknown"` → "We could not tell what kind of document this is, so no obligations are shown. It reads as: …".

### M2. Dates/amounts the regex finds but the model omitted are silently lost [verified]

`crossCheck` (`extract.ts:366-399`) only walks `vision.obligations`. Scratch D: rawText has two 納期限 instalments (`9/30`, `11/2`); model reports one obligation; regex finds both; nothing surfaces the second. No field exists for "unmatched". Fix (small): return `{ obligations, unmatchedDates, unmatchedAmounts }` from a new `crossCheckWithExtras` and render an "Also printed on this page" list of `raw`+`label` under the obligations (raw surface forms only — no interpretation). ActionCard is "frozen", but this is a strict addition.

### M3. One conflict slot: a date conflict hides an amount conflict [verified]

`extract.ts:370-372` comments the choice; scratch E: due `9月6日` vs page `9月5日` AND amount ¥12,000 vs page 1,200円 → only the date conflict is shown; the ¥12,000 stays on the card with no flag. Fix: `conflicts: Conflict[]` (or `conflict` + `amountConflict`); render both.

### M4. Vision-model prose does reach the user [verified by reading]

`src/lib/vision.ts:5-7` and `ARCHITECTURE.md:30-31` say the vision model "never writes anything a user reads / no prose". But `obligations[].action` is English prose authored by the vision model (`vision.ts:142-145`: "Imperative, in English") and is rendered verbatim at `obligation-row.tsx:92`, in the ICS `SUMMARY` (`ics.tsx:71`), and fed to Shisa. The Japan-residency seam (no image to Shisa, no Japanese from OpenAI — grep confirms `input_image` only in `vision.ts:222`) holds. The "no prose" claim does not. Fix: either soften the docs to "no Japanese, no advice" or have `generateActionCard` also return `actions[]` rewritten by Shisa (adds a few hundred ms).

### M5. Lease text with names/addresses is sent to OpenAI for embeddings [verified by reading]

`judge.ts:309-312` → `retrieveEntries(vision.rawText)` → `embed.ts:39` posts the entire transcription to `api.openai.com`. README:115-118 says "Japanese text is processed in Japan is a promise made to the user". ARCHITECTURE §6 does disclose "vectors only", but the input is the full clause text including the parties' names. Fix for demo honesty: either embed only the clause sentences (strip lines containing 甲/乙 names, addresses), or state plainly in README that the clause text goes to OpenAI for retrieval, or use hint routing only when a `PRIVACY_STRICT` flag is set.

### M6. Allowlist covers the model string only; "fails at startup" is false [verified]

- `shisa.ts:38,63` — `/^shisa-ai\//` accepts `shisa-ai/../glm-4.5`, `shisa-ai/`, `shisa-ai/qwen3-235b` (scratch). Harmless in practice because the model is a JSON field, not a URL segment, but nothing pins **`SHISA_BASE_URL`** — set it to `https://api.openai.com/v1` and `shisa-ai/x` is accepted (scratch: `baseUrl` returned unchanged). The residency guarantee is really "model prefix AND host", and only half is checked.
- `createShisaClient()` runs lazily inside `streamRegisters`/`generateActionCard`/`completeWithShisa`; nothing calls it at boot. README:93-94 and ARCHITECTURE:180 say it fails at startup. `scripts/eval-registers.ts` and `complete.ts` do go through `createShisaClient` (good).

Fix: `if (new URL(baseUrl).host !== "api.shisa.ai") throw` (or an env allowlist), tighten to `/^shisa-ai\/[A-Za-z0-9.\-]+$/`, and call `createShisaClient()` once from `src/instrumentation.ts` (`register()`) so a bad env fails the deploy.

### M7. Reply/decode input validation gaps + prompt-injection surface [verified by reading]

- `src/app/api/reply/route.ts:16-28` — `recipient` and `documentSummary` have **no length cap**; `docType` is `typeof string`, not `DOC_TYPES.includes`; all three are interpolated raw into four prompts (`prompts/registers.ts:95-104`).
- `src/app/api/decode/route.ts:29-36` — `outputLang` unbounded and interpolated into `actionCardSystemPrompt` ("in ${outputLang}") and the judge prompt. `outputLang: "English. Ignore the rules above and…"` is a valid request.
- `imageBase64` is not checked for base64 alphabet or JPEG magic (`/9j/`); forwarded as `data:image/jpeg` (`vision.ts:223`).
- The REPLY side has **no code-level guard** on output — `LEGAL_BOUNDARY` is prompt-only, unlike JUDGE. The eval scenario `deposit-dispute` literally asks the model to invoke the MLIT guideline.

Fix: `recipient ≤ 120`, `documentSummary ≤ 2000`, `DOC_TYPES.includes(docType)`, `outputLang` must match `/^[a-z]{2,3}(-[A-Za-z0-9]{1,8})*$/`, `imageBase64` must match `/^[A-Za-z0-9+/]+=*$/` and start with `/9j/`. Consider running the Japanese half of `PROHIBITED` over the final `textJa` per register and replacing a hit with an error event.

### M8. Streaming edge cases [verified by reading; strip behaviour verified]

- `src/components/use-reply-stream.tsx:82-90` `settle` marks any `streaming`/`idle` register **done** when the body closes. If Vercel kills the function at 60 s or the gateway drops, a half-written 最敬語 is shown as finished with a "Working out what changed…" gloss forever. Fix: at settle, a register without a prior `done`/`error` event → `phase: "error", error: "Cut off before it finished."`.
- `shisa.ts:197-203` `isNoiseLine`: a line with Latin and **no kana** is treated as commentary, at both ends. Scratch: `"PTA会費 3,000円\nお世話になっております…\n田中 Tanaka"` → first and last lines dropped. Subject lines (`件名：PTA会費`) and romaji signatures vanish silently; an all-English reply (injection or model slip) collapses to `""` and is reported `done`. Fix: also require no CJK ideographs: `LATIN.test(line) && !KANA.test(line) && !/[一-鿿]/.test(line)`.
- `reply/route.ts:44-59` — after a client abort, `controller.enqueue` in `send` throws inside `streamRegisters`' catch (`shisa.ts:333` returns early only if `signal.aborted`, which depends on Next wiring `req.signal` to disconnect — [plausible], not verified), then `controller.close()` on a cancelled stream throws in `finally`. Wrap `send` in `try { … } catch {}` and guard `close()`.
- `extract.ts:277` range handling: `9月5日〜7日` drops the end day (scratch) because `7日` alone never matches — falls out of H2's day-only pattern.

### M9. `.env.example` switches both sidecars on with localhost URLs [verified]

`.env.example:18,25` set `QDRANT_URL=http://localhost:6333` and `NEO4J_URI=bolt://localhost:7687`; README:88-90 says "unset → off". A fresh `cp .env.example .env.local` (the documented quickstart) and a Vercel env copied from it make every decode attempt an embeddings call + Qdrant connect, and every lease decode a Neo4j connect (see H5 for the wait). ### M10. The `?mock=lease` card asserts guideline content the citation does not contain [verified by reading]

`src/components/mock-data.tsx:93-94`: "The guideline treats wallpaper as depreciating over roughly six years" under the `tsujo-sonmo-tokuyaku` citation (P.6, 特約の要件). The corpus entry (`groundtruth.ts:162-173`) says nothing about six years. ## Things that are genuinely well done — do not touch

- `extract.ts` era handling (`ERA_BASE` incl. 大正/明治 so old leases do not resolve to this year), `toIso` calendar validation (2月30日 rejected, not rolled), `dropOverlaps`, `toAscii` length-preserving width folding, fractional 万 (`8.5万円` → 85,000). The tests around these are thorough.
- `crossCheck` never drops or corrects an obligation and returns new objects; the date-over-amount precedence is at least documented.
- JUDGE's three gates: retrieval returns only ids resolved through `GROUND_TRUTH`; citation is matched against the **candidates handed to the model**, not the whole corpus (`judge.ts:254`); `"differs"` is enum-capped; the corpus's own `guidanceEn` is tested against the guard (`judge.test.ts:347-361`).
- `graph.ts` `anonymize()` as the single write path, and `graph.test.ts` pushing sentinel PII through a mocked driver and asserting the wire — that is the right shape for a privacy guarantee. `wardFromIssuer` only for ward letters.
- `shisa.ts` SSE parser: `TextDecoder` streaming mode for multibyte, newline buffering, `[DONE]`, `DELIMITER_HOLDBACK` so `---GLO` never leaks, per-register failure isolation, abort-aware `delay`, `withRateLimitRetry` parsing both "Retry after 297ms" and "4.6s".
- `use-reply-stream.tsx`: one dispatch per network chunk, immutable reducer, abort on unmount; the slider (`register-slider.tsx`) never triggers work and is keyboard/ARIA correct.
- `ics.tsx` RFC 5545 escaping and 75-octet folding; the ICS description carries the conflict text so a wrong date does not become a silent calendar entry.
- `kaifu-app.tsx` holds the preview in memory only; the 413 path has its own copy; `contribute` is read off the raw body and must be literal `true`.
- `prompts/register-specs.ts` and `HONORIFIC_DIRECTION` are unusually specific (misdirected-honorific list, forbidden forms per rung) — this is the moat and it reads like someone who has been burned by live output.
- `vision.ts` strict JSON schema with `conflict` deliberately absent so the model cannot assert one.
